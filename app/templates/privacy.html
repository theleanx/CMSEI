Privacy

Draft. This text describes how the software behaves. It has not been reviewed by counsel. Operator-level details (hosting logs) depend on how the site is deployed.

What the software stores

  • The score for each material. The same for everyone.
  • A resolved material id for each assessment, the rule ids of the suggestions shown, and a timestamp. Nothing else about the assessment.
  • A watchlist, only if you add a material. It is tied to a random token kept in a cookie. Only a hash of the token is stored. You can delete it on the Watchlist page.
  • Counts by category and day (which material was checked, which tier). Linked to an anonymous session hash only if you have a session.

What the software does not store

  • The text you type to describe a material. It is used once, in memory, to find the category. It is not written to the database or to application logs.
  • Your sourcing region and volume. They choose which suggestions are shown and are not stored.
  • Your name, email, company or account. There are none.
  • Application logs hold only the method, route, status code and timing. They do not hold query strings, request bodies or IP addresses.

What this does not cover

  • The hosting provider and any network layer in front of the site may keep their own request logs, including IP addresses. The operator can configure these but this software cannot guarantee it.
  • When an AI model is used to find the category, your short text is sent to the model provider for that one call. The offline matcher is used when no model is configured. Check the provider's retention settings before relying on this.
  • Session identifiers and IP addresses can count as personal data under some state laws. Counsel review is pending.
